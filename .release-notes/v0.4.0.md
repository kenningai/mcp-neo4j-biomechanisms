# v0.4.0 — Kenning Soma

The project is now **Kenning Soma**, joining Kenning Continuity and Kenning Encounter under a common identity. Nothing about the graph, the schema, or the tool surface changes — this release is the rename and the packaging that follows from it.

## Breaking

- **The distribution is now `kenning-soma`.** Install `kenning-soma`; `mcp-neo4j-biomechanisms` will not receive further releases. Existing versions of the old name remain on PyPI and keep working, so nothing installed today breaks.
- **The import package is now `kenning_soma`** (was `mcp_neo4j_biomechanisms`).
- **The console entry point is now `kenning-soma`** (was `mcp-neo4j-biomechanisms`). Update any MCP client config that launches the server by command name:

  ```diff
  - "command": "mcp-neo4j-biomechanisms"
  + "command": "kenning-soma"
  ```

- The Docker image is `kenningai/kenning-soma`, pinned to `0.4.0`.

## Unchanged, deliberately

- **Your graph needs no migration.** The fulltext index is still `biomechanisms_index`, every node label and relationship type is identical, and all tool names and signatures are the same. Point `0.4.0` at an existing database and it will work.
- The domain vocabulary keeps the word *biomechanism*. Soma is what the tool is called; biomechanism is what it models — the claim that conscious experience is expressed in biological **mechanism**, not merely correlated with it. `biomechanisms.py` and the `Neo4jBiomechanisms` class keep their names for the same reason.

## Validation

- `uv run pytest tests/unit` — 55 passed.
- Both distributions install into a clean environment and run the entry point.
